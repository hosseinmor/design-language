# وضعیت‌های خالی

این سند قرارداد انسانی وضعیت‌های خالی است. قواعد machine-readable در
[`empty-states.yml`](empty-states.yml) و نمونه‌های regression در
[`../../../ai/evals/content/empty-state-cases.yml`](../../../ai/evals/content/empty-state-cases.yml) قرار دارند.

## هدف

وضعیت خالی باید سه سؤال را پاسخ دهد:

1. چه محتوایی اکنون وجود ندارد؟
2. اگر علت معلوم و مفید است، چرا؟
3. کاربر برای ایجاد محتوا، تغییر شرایط یا ادامهٔ task چه کاری می‌تواند انجام دهد؟

وضعیت خالی یک صفحهٔ تزئینی یا فرصت تبلیغاتی نیست. وظیفهٔ آن حفظ جهت‌یابی و
پیش‌بردن کاربر است.

## ابتدا وضعیت را درست طبقه‌بندی کنید

| وضعیت | معنی | وظیفهٔ محتوا |
|---|---|---|
| استفادهٔ نخست | کاربر هنوز آیتمی ایجاد یا ذخیره نکرده است | ارزش مجموعه و اقدام شروع را توضیح دهید. |
| مجموعهٔ خالی | در وضعیت فعلی آیتمی وجود ندارد | مجموعه و اقدام معتبر بعدی را نام ببرید. |
| بدون نتیجه | query یا فیلتر فعلی نتیجه ندارد | شرایط فعال و راه تغییرشان را نشان دهید. |
| شروع سرد | دادهٔ کافی برای محتوای شخصی‌سازی‌شده وجود ندارد | requirement تأییدشدهٔ شروع را توضیح دهید. |
| خالی پس از حذف | آخرین آیتم با اقدام کاربر خارج شده است | زمینه و مقصد بعدی را حفظ کنید. |

موارد زیر empty state نیستند:

- Loading: هنوز معلوم نیست داده‌ای وجود دارد یا نه.
- Error: داده دریافت یا پردازش نشده است.
- Permission: داده ممکن است وجود داشته باشد، اما کاربر اجازهٔ دیدن آن را ندارد.
- Eligibility: کاربر هنوز شرط دسترسی یا استفاده را ندارد.

پنهان‌کردن این وضعیت‌ها پشت عبارت «موردی وجود ندارد» product truth را از بین
می‌برد و ممکن است کاربر را به اقدام اشتباه هدایت کند.

## قرارداد قطعی

### باید

- نوع وضعیت را پیش از نوشتن مشخص کنید.
- محتوای خالی را با نام قابل‌فهم و مطابق UI بنویسید.
- علت را فقط وقتی بگویید که از وضعیت واقعی محصول معلوم است.
- وقتی اقدام معتبر وجود دارد، یک گام اصلی معنادار ارائه کنید.
- در no-results، query یا فیلترهای مؤثر و راه تغییرشان را روشن کنید.
- بعد از خالی‌شدن پویا، جهت‌یابی، فوکوس و اعلام وضعیت را حفظ کنید.

### نباید

- کاربر را برای نداشتن داده سرزنش یا شرمنده کنید.
- رسیدن، تعداد، کیفیت یا زمان محتوای آینده را وعده دهید.
- فقط بنویسید «چیزی اینجا نیست» یا «موردی وجود ندارد».
- CTA غیرواقعی، غیرمجاز یا بی‌اثر بسازید.
- Error، Loading، Permission یا Eligibility را empty state معرفی کنید.
- تصویر یا شوخی را جای توضیح وضعیت و اقدام قرار دهید.

## ساختار

```text
عنوان اختیاری     → چه چیزی خالی است
توضیح              → علت معلوم یا ارزش مجموعه
اقدام اصلی اختیاری → ایجاد محتوا، تغییر شرایط یا مقصد مرتبط
اقدام دوم اختیاری  → فقط یک مسیر مستقل و واقعاً مفید
```

پیام باید بدون تصویر هم کامل باشد. آیکن یا تصویر می‌تواند از درک حمایت کند،
اما معنی وضعیت یا action نباید فقط در تصویر باشد.

## استفادهٔ نخست

```text
عنوان: هنوز آگهی‌ای ذخیره نکرده‌اید
توضیح: آگهی‌های شغلی موردنظرتان را ذخیره کنید تا بعداً دوباره بررسی‌شان کنید.
اقدام: مشاهدهٔ آگهی‌های شغلی
```

این متن «آگهی ذخیره‌شده» را با «جست‌وجوی ذخیره‌شده» یکی نمی‌گیرد و action را
با مقصدش نام می‌برد.

نمونهٔ جست‌وجوی ذخیره‌شده:

```text
عنوان: هنوز جست‌وجویی ذخیره نکرده‌اید
توضیح: جست‌وجوی خود را ذخیره کنید تا بعداً با همان شرایط به نتایج برگردید.
اقدام: جست‌وجوی شغل
```

## بدون نتیجهٔ جست‌وجو یا فیلتر

```text
عنوان: آگهی شغلی‌ای با این جست‌وجو پیدا نشد
توضیح: عبارت جست‌وجو یا فیلترها را تغییر دهید.
اقدام: پاک‌کردن فیلترها
```

اگر فقط یک شرط فعال است، آن را مشخص‌تر بنویسید:

```text
برای «طراح محصول» در شیراز آگهی شغلی‌ای پیدا نشد.
```

عبارت «هیچ آگهی‌ای وجود ندارد» نادرست است؛ ممکن است آگهی وجود داشته باشد اما
شرایط فعلی نتیجه‌ای برنگردانده باشد.

## شروع سرد و محتوای شخصی‌سازی‌شده

```text
عنوان: هنوز پیشنهادی برای شما نداریم
توضیح: برای شروع، ترجیحات شغلی خود را تکمیل کنید.
اقدام: تکمیل ترجیحات شغلی
```

این متن فقط وقتی مجاز است که محصول تأیید کند تکمیل ترجیحات requirement واقعی
تولید پیشنهاد است. در غیر این صورت، علت یا action را حدس نزنید.

نگویید «به‌زودی بهترین فرصت‌ها را برای شما پیدا می‌کنیم»؛ زمان، کیفیت و رسیدن
پیشنهاد جدید تضمین نشده است.

## وقتی action معناداری وجود ندارد

وجود CTA اجباری نیست. اگر کاربر نمی‌تواند وضعیت را تغییر دهد، یک action بی‌اثر
یا مقصد نامرتبط نسازید:

```text
گزارش این بازه اکنون داده‌ای ندارد.
```

اگر علت یا بازه معلوم است، آن را اضافه کنید. اگر نیست، توضیح ساختگی ندهید.

## خالی‌شدن پویا

وقتی کاربر آخرین آیتم را حذف، جابه‌جا یا از فیلتر خارج می‌کند:

- نتیجهٔ action را با الگوی feedback اعلام کنید؛
- فوکوس را روی body رها نکنید؛
- فوکوس را به عنوان مجموعه، action وضعیت خالی یا مقصد منطقی دیگری ببرید؛
- اگر Undo واقعاً وجود دارد، آن را طبق رفتار محصول ارائه کنید؛
- empty state را جای success feedback استفاده نکنید.

## انتخاب action

| وضعیت | action مناسب |
|---|---|
| استفادهٔ نخست | ایجاد اولین آیتم یا رفتن به مسیر کشف |
| بدون نتیجه | پاک‌کردن فیلتر، تغییر جست‌وجو یا گسترش محدوده |
| شروع سرد | تکمیل requirement تأییدشده |
| خالی پس از حذف | مقصد بعدی مرتبط یا Undo تأییدشده |

action و destination را نام ببرید. «شروع کنید»، «ادامه» یا «اینجا کلیک کنید»
به‌تنهایی جهت کافی نمی‌دهند.

## مرز با خطا

```text
درخواست به سرور ناموفق بوده است
→ Error، نه Empty State

درخواست موفق بوده و مجموعه واقعاً صفر آیتم دارد
→ Empty State
```

در وضعیت نامعلوم، empty state نمایش ندهید. برای خطا از
[`errors.md`](errors.md) استفاده کنید.

## لحن

پروفایل empty state وضوح زیاد، گرمی متوسط، انگیزش متوسط و بیان برند متوسط دارد.
این آزادی فقط برای کمک به جهت‌یابی است:

- گرمی به‌معنی شکسته‌نویسی یا خطاب بیش‌ازحد خودمانی نیست.
- انگیزش به‌معنی وعدهٔ نتیجه نیست.
- بیان برند به‌معنی استعاره، شوخی یا شعار در هر وضعیت خالی نیست.
- اگر وضعیت به موضوع حساس، دسترسی یا از‌دست‌رفتن داده نزدیک است، بیان برند را
  کاهش دهید.

## چک‌لیست بازبینی

- [ ] نوع وضعیت خالی مشخص است.
- [ ] Error، Loading، Permission و Eligibility کنار گذاشته شده‌اند.
- [ ] entity یا مجموعه با اصطلاح درست نام‌گذاری شده است.
- [ ] علت و requirement فقط از product truth آمده‌اند.
- [ ] action وضعیت را تغییر می‌دهد یا به مقصد مرتبط می‌برد.
- [ ] در no-results، شرایط فعال و recovery روشن‌اند.
- [ ] متن نه generic است، نه سرزنش‌گر و نه وعده‌دهنده.
- [ ] پیام بدون تصویر هم قابل‌فهم است.
- [ ] رفتار فوکوس و اعلام وضعیت بعد از تغییر پویا تعریف شده است.
